## Reporting a Vulnerability

We take the security of `polars-datapulse` and its users seriously. If you discover a security vulnerability, please report it responsibly.

### How to Report

**Please DO NOT open a public issue.** Public disclosure exposes users before a fix can be released.

Instead, please report security vulnerabilities through either of the following channels:

1. **GitHub Private Vulnerability Reporting (Preferred):**  
   Go to the [Security Advisories tab](https://github.com/Mr-Rup/polars-datapulse/security/advisories) on GitHub and click **"Report a vulnerability"**.
2. **Direct Security Email:**  
   Send an encrypted or private email to **Biswarup Majumdar** at:  
   📧 **`majumdarb107@gmail.com`**

### What to Include in Your Report

To help us triage and resolve the issue quickly, please provide:
- A clear description of the vulnerability.
- Steps to reproduce the issue (including sample datasets or scripts if applicable).
- The potential impact of the vulnerability (e.g., denial of service, memory exhaustion, information disclosure).
- Any proposed remediation or patches, if available.

### Response Timeline

- **Initial Acknowledgement:** Within **48 hours** of receiving the report.
- **Triage & Status Update:** Within **5 business days** with an assessment of severity and impact.
- **Fix & Release:** We will coordinate a patched release and credit the reporter in release notes (unless anonymity is requested).

## Security & Privacy Considerations in DataPulse

- **Local Execution:** DataPulse runs entirely locally on your machine or container. No dataset contents, schemas, or metrics are ever transmitted over the network or to external servers.
- **Zero CDN Dependencies:** HTML reports generated by DataPulse are completely self-contained. All styles, SVGs, and interactive JavaScript scripts are bundled inline, preventing external CDN supply chain attacks and tracking.
- **Path Privacy:** By default, report metadata includes only the base filename (`include_full_path = False`), preventing unintentional leakage of local usernames or directory hierarchies when sharing reports.
- **XSS Protection:** All user strings, column names, categories, and statistics embedded within HTML reports are strictly escaped using standard HTML entity encoders to prevent Cross-Site Scripting (XSS).
